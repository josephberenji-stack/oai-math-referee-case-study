## 2. The mechanism (the "how")

1. **CM splits H¹ into characters.**  With complex multiplication by a CM field E, H¹ decomposes into one-dimensional
   pieces indexed by the embeddings of E, so H^{2p} has a basis of monomials (wedge products of those pieces).  Each
   monomial carries a sign pattern over Gal(E/ℚ);  it is a Hodge class exactly when its signs balance
   (FourFactorSwitches.lean:41-56, the `signSum` step).
2. **Reduce to monomials.**  A rational Hodge class is algebraic if every Hodge monomial in it is
   (`rational_hodge_mem_geometric_of_monomials`, `monomial_algebraic_of_endpoint`).
3. **Connect monomials by switches.**  Any Hodge monomial is joined to known algebraic classes (Lefschetz (1,1),
   degree two) by a path of "pair switches" (`connectivity_by_pair_switches`;  `endpointAlgebraicity_of_PairSwitches`).
4. **The one new geometric input:  four-factor switches.**  Each switch is a class on a product of four CM abelian
   varieties whose signs balance as v0 + v1 = v2 + v3 (CMReduction/Definitions.lean:19).  These are where the classes
   not generated by divisors live (the Weil-type classes).  The submission's claim is that each such class is
   realized by an explicit algebraic cycle, built from a surface inside the fourfold product
   (`algebraic_cycle_realizing_switch`;  the input is named `p54_input`, CycleCoefficientsP.lean:13, which reads as a
   reference to page 54 of a manuscript).
5. **Everything else is classical**, supplied as proved theorems:  Lefschetz (1,1), Riemann's projectivity criterion,
   Hodge decomposition, resolution of singularities (`Resolution.Blowups.Strong`), cycle classes are Hodge.

So the argument stands on step 4:  the explicit surface cycle for each balanced four-factor class.  That is the place
to study.

## 5. The "Established" pattern (added 28 Oct 2026 ~21:35 UTC, static reading)

Every stage of the Hodge proof is first stated with named hypotheses ("…Input", "KnownResults…"), and an `Established`
file then supplies each hypothesis as a proved theorem, so the final theorem carries none; they are discharged one stage
at a time. The files (under `OAI/AlgebraicGeometry/`):

| file | lines | supplies |
|---|---|---|
| `HodgeConjecture/CMReduction/Established.lean` | 125 | the 12 inputs of the main reduction, including the four-factor switch |
| `HodgeConjecture/Established.lean` | 90 | the surface construction's inputs (scalar trace descent, degree-two algebraicity, Lefschetz (1,1), cycle-class compatibility) |
| `HodgeConjecture/DegreeTwo/Established.lean` | 69 | the degree-two step's inputs (`e06Input`–`e08Input`) |
| `HodgeConjecture/HeckeCycles/Established*.lean` | 8 files | the Hecke-cycle inputs (`spherical_hecke`, `theta_covariance`, and others) |

For the referee: the hypothesis-taking stages are where L2 (a hypothesis nothing builds) looks, and the `Established`
files are the evidence that each is built; H1 and H2 check that the supplied proofs use only the three axioms and no
placeholders. A per-stage table (stage theorem → its inputs → the `Established` theorem supplying each) is to be read
off the compiled constants in the Hodge pass.
